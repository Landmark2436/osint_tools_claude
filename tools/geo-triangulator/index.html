    Help & user guide

    Quick start

    1. Add measurement points: click on the map (toggle “Add point on map click”), use “+ Add row”, import a file, or load an example.
    2. For each point enter a radius (distance to the target in metres) and/or a bearing (direction to the target in degrees, clockwise from true north, 0 = north, 90 = east).
    3. Optionally enter uncertainties (σ = one standard deviation). They weight the measurements in the adjustment.
    4. The result updates automatically. In “Automatic” mode the app picks the matching method and shows which one it used.

    Modes

    • 1 · One radius: the target lies inside (or on) the circle. Area and circumference are shown. One circle cannot fix a position.
    • 2 · Two radii: the lens-shaped intersection area and the two intersection points (the target is at one of them if the radii are exact distances). If the circles don’t meet, the point of least weighted deviation is shown.
    • 3 · Three or more radii: least-squares estimate (Levenberg–Marquardt) with error ellipse, plus the area common to all circles if there is one.
    • 4 · Bearings: intersection of the bearing rays; with more than two bearings a least-squares adjustment. Parallel rays and rays meeting behind an observer are reported. The shaded area is the intersection of the ±2σ bearing cones.
    • 5 · Mixed: radii and bearings in one joint, weighted adjustment. A single point with both radius and bearing already gives a position (polar fix).
    • 6 · Delaunay: triangle mesh of the points (no target estimate). Automatic mode uses it when points have neither radius nor bearing.

    Reading the result

    • Red crosshair: estimated position (purple: alternative, equally good solution). The coordinates can be copied.
    • Error ellipse (dashed): 95 % confidence region. “95 % radius” is the major semi-axis, i.e. a circle that contains the ellipse.
    • s₀ (a-posteriori standard deviation of unit weight) ≈ 1 means the measurements agree with their σ. s₀ > 3 indicates contradictory data. The covariance is then scaled by s₀².
    • Residuals are “computed − observed”, evaluated on the sphere. |v/σ| > 3 is flagged in red as a likely outlier.

    Files

    CSV with a header line, separated by , ; or tab: name,lat,lon,radius_m,sigma_radius_m,bearing_deg,sigma_bearing_deg,visible. Common alternatives (latitude, lng, distance, azimuth…) are recognised; empty cells are allowed. With ; as separator a decimal comma is accepted.
    GeoJSON: Point features; the same names are read from properties.

    Notes & limits

    • Calculations run on a spherical earth (R = 6371 km) in a local azimuthal equidistant projection. Accuracy is excellent up to several hundred kilometres; don’t use it across the poles or the ±180° meridian.
    • Everything runs locally in your browser; inputs are stored only in this browser’s localStorage. Nothing is uploaded except map tile requests.
    • If the map shows “Access blocked / Referer required”, the OpenStreetMap tile server is refusing requests from a local file. Choose another base map with the layer button (top right of the map), or put the file on a web server.
